# Mod Readme — Jak 3 Jetboard Mechanics Port to Jak 2

> **Game:** Jak 2  
> **Branch:** `jak2/features/jak3-jetBoard`  
> **Target Subsystem:** Target Jetboard (`goal_src/jak2/engine/target/board/`) & Sound Bank / Art Group Pipelines

---

## 1. Description & Features

This mod ports three core Jetboard mechanics introduced in Jak 3 into Jak 2's native jetboard system:

1. **Chargeable High Jump:**
   - **Controls:** Hold `L1` (crouch on board) then release `X` / Jump.
   - **Behavior:** Charges dynamic upward kinetic energy and launches Jak much higher than standard board jumps (`jakb-board-jump-high-ja`). Plays dedicated charge & launch audio.
2. **Board Zap Attack (Area-of-Effect & I-Frames):**
   - **Controls:** Press `Circle` while riding the board.
   - **Behavior:** Unleashes a radial electric shockwave dealing damage to nearby enemies with invincibility frames during the discharge. Plays `BOARD_ZAP` and `BOARD_ZAP_HIT`.
3. **180-Degree Quick Turn-Around:**
   - **Controls:** Press `Triangle` while riding the board.
   - **Behavior:** Executes a rapid 180° snap rotation (`jakb-board-turn-around-ja`). Upon completing the rotation, triggers a speed boost forward with vibration, landing dust particles, and the native `"board-boost"` sound effect (matching the spin-trick boost reward).

## 2. Technical Architecture & Tooling

### A. Animation Retargeting Pipeline (`retarget_anim` & `CMakeLists.txt`)
To cleanly import Jak 3 animations into Jak 2 without manual Blender edits or hex manipulation, a dedicated standalone C++ tool was integrated into the OpenGOAL toolchain:

- **`goalc/CMakeLists.txt` :**
  - Declares executable target `retarget_anim` (`add_executable(retarget_anim retarget_anim/main.cpp retarget_anim/retarget_anim.cpp)`).
  - Links `common`, `fmt`, and `tiny_gltf` to directly read, process, and write binary glTF/GLB containers.
- **`goalc/retarget_anim/main.cpp` :**
  - Provides a CLI interface (via `CLI11`) to configure retargeting:
    - `--base` (`-b`): Base reference GLB carrying Jak 2's native mesh and skeleton (`jakb-lod0.glb` / `daxter-lod0.glb`).
    - `--source` (`-s`): Source GLB containing raw extracted animations from Jak 3.
    - `--anim` (`-a`): Exact animation names to retarget (`board-jump-high`, `board-turn-around`).
    - `--root-joints`: Joints receiving true root motion translation and rotation (`align`, `main`).
    - `--neutral-scale-joints`: Sockets protected from scale drift (`board`).
- **`goalc/retarget_anim/retarget_anim.cpp` :**
  - **Bone-by-name matching:** Maps animation tracks to Jak 2 skeleton joints by semantic name, bypassing joint index discrepancies.
  - **Stretching elimination:** Retains translation only on root bones (`align`/`main`) and forces pure rotation (quaternions) on all child bones to preserve natural limb lengths.
  - **Attachment scale preservation:** Keeps native bind-pose scale on joint 25 `board` (`(0.7143, 0.7143, 0.7143)` canceling `main`'s `1.4` scale).
  - **GLTF spec compliance:** Automatically converts `JOINTS_0` accessor from `UNSIGNED_INT` to `UNSIGNED_BYTE` for `gltf_util` compatibility and purges orphaned buffer data, so the output holds only the 2 needed animations without polluting the package.

### B. Sound Bank Injection (`SBK` Tooling)
- **`decompiler/data/extract_sbk.cpp` & `goalc/build_sbk/` :** C++ tools to extract ADPCM audio from `.SBK` banks and inject new samples via `append-sbk` macro in `project-lib.gp`.
- **`custom_assets/jak2/sounds/sfx/MODEBORD/` :** Provides the 4 Jak 3 audio files (`BOARD_CHARGE`, `BOARD_LAUNCH`, `BOARD_ZAP`, `BOARD_ZAP_HIT`).

### C. Dynamic Art Linking & GOAL Gameplay Logic
- **`goal_src/jak2/engine/anim/joint.gc` :** Hook inside `art-group::relocate` to dynamically link custom art groups at file load time (`link-art!`).
- **`goal_src/jak2/engine/target/board/board-h.gc` :** Extended `board-info` and `target-board-bank` to hold charge timers, zap duration, and sound IDs.
- **`goal_src/jak2/engine/target/board/board-states.gc` & `target-board.gc` :** Implemented high jump, quick turnaround, and zap attack state machines with radial damage collision and i-frames.

## 3. How to Test & Play

1. Set the active game to Jak 2:
   ```bash
   task set-game-jak2
   ```
2. Build custom sound assets and recompile:
   ```bash
   task extract
   ```
3. In REPL (`task repl`), hot-recompile code:
   ```lisp
   (mi)
   ```
4. Boot the game:
   ```bash
   task boot-game
   ```
5. **Enable the mod** (it ships OFF by default — mandatory non-regression rule):
   open the debug menu and go to **`Debug ▸ Mods ▸ jak3-jetboard ▸ Enable (master)`**.
   Toggling the master ON also arms the three per-mechanic rows below it; you can
   then switch any single mechanic (`Loaded Jump` / `Zap Attack` / `Turn-Around`)
   off independently. With the master OFF the jetboard plays exactly like stock.
6. Equip Jetboard (`R2`) and test:
   - **Charge Jump:** Hold `L1`, release `X`.
   - **Zap Attack:** Press `Circle`.
   - **Quick Turn:** Press `Triangle`.

## 4. Current Status & Investigations

- **Compile & Boot Status:** Full compilation and boot verified on Jak 2 with all 3 mechanics operational.
- **Visual Glitches Fixed at Source (1st playtest round):**
  - *Board scale fix:* The generator previously hardcoded `board` scale to `(1,1,1)`. In Jak 2's native bind-pose, `board` has scale `(0.7143,0.7143,0.7143)` as a child of `main` (scale `1.4`), canceling out the parent scaling. Fixed by retaining native bind-pose scale.
  - *Turn-around rotation fix:* Removed forced 180° yaw on `align` in the GLB, as `target-board-turn-around` (`board-states.gc`) already drives the 180° rotation entirely through gameplay code (`quaternion-rotate-y!` and `align!`).
- **Particle Effects Fixed (2nd playtest round):**
  - *Missing charge-up glow:* The `charge-part` struct field existed but no `create-launch-control` or per-frame `spawn` call had ever been wired up. Added `group-target-board-duck-charge` (id 1295) to `board-part.gc`, created the launch control in `target-board-init`, and added the per-frame `spawn` call in `target-board-real-post` (gated on `charge-progress != 0`) — mirrors Jak 3's own logic exactly (`target-board.gc:2215-2224`).
  - *Wrong zap effect:* The zap attack was mistakenly reusing `group-board-spin-attack`, the native spin-trick effect, unrelated to the zap. Added a dedicated `group-board-zap-attack` (id 1296) and moved the attach point from a hand-computed offset to the `hips` joint (index 25 in Jak 2, 37 in Jak 3 — same joint name, different skeleton index, confirmed by direct inspection of both skeletons), matching Jak 3's real implementation.
  - *Missing textures:* Jak 3's original effects reference textures (`laser-hit2`, `laser-hit-rim`) absent from Jak 2's asset set (confirmed via `decompiler/config/jak2/ntsc_v1/tex-info.min.json`). Substituted with `starflash` and `water-ring`, both already native to Jak 2 (`water-ring` is already used by the native `group-board-spin-attack`) — this is the same substitution strategy the `og-j1-board` mod used for the identical problem, not an improvised choice.
- **Cosmetic Note:** Console output `-debug` prints `no eye anim data for target/sidekick` on new animations because there are no eye blink table entries for custom animation clips (neutral eye pose fallback, harmless).
- **Crash + Joint Fixes (3rd playtest round):**
  - *Zap attack crash (game-breaking):* `part-tracker-spawn`'s `:target` argument is broken in Jak 2's macro — `part-tracker-init` (`generic-obs.gc`) casts the macro's constant `*launch-matrix*` pointer straight to an `int` for `target-joint` whenever `:target` is set, regardless of what `:mat-joint` was, producing a garbage joint index and an out-of-bounds `node-list` read on every zap. On top of that, the custom `board-zap-track` particle callback read `node-list` off `key proc`, which for a `part-tracker`-spawned effect is the ephemeral tracker process itself (no skeleton, no `node-list`) — a second, independent null dereference. Jak 3's own call (`:mat-joint 37` as a raw int, with an explicit tracker-type argument) relies on a different, incompatible macro signature, so it wasn't portable as-is. Fixed by dropping `:target` and the custom callback entirely, following Jak 2's own working native precedent (`group-board-spin-attack`, spawned the same way with a plain snapshotted `:mat-joint` vector and `sparticle-track-root` instead of a custom joint lookup).
  - *Charge glow anchored to the wrong joint:* `board-charge-track` used joint index 25 for "board", but direct inspection of `jakb-lod0.glb`'s skin joint order shows index 24 = `board`, 25 = `hips` — the glow was actually following the hips. Corrected to 24.
- **Positioning fixes (4th playtest round):** the crash fix above visibly worked (charge glow visible, zap effect matches Jak 3), but surfaced 2 more precise issues:
  - *Charge glow position still wrong even at index 24* (landed near the head, not the board) — proof that hand-counting a GLB's skin joint list doesn't reliably match this joint-group's real compiled index (got it wrong twice: 25, then 24). Replaced both `board-charge-track`'s hardcoded index and the zap trigger's with `(joint-node-index jakb-lod0-jg board)` / `(joint-node jakb-lod0-jg hips)` — a compile-time name-based lookup against the real `jakb-lod0-jg` joint-group data, the same mechanism every other native joint lookup in the game already relies on, instead of a manually-counted number.
  - *Turn-around: momentum doesn't reverse, character sinks into the ground, animation looks broken* — deep investigation, not yet resolved at the time. Compared `target-board-turn-around` line-by-line against Jak 3's native state: the 3 apparent differences (`compute-alignment!` vs `compute-delta-align!`, the `target-align-vel-z-adjust`-wrapped velocity formula, `dynam` vs `standard-dynamics`) all turned out to be correct, necessary Jak 2 API adaptations (`compute-delta-align!` doesn't exist in Jak 2 at all; the other two are Jak 2's own native idiom, used identically in `target.gc`/`target-darkjak.gc`/`target-indax.gc`). The velocity-reversal formula reads `(-> self align delta trans z)`, which `compute-alignment!` derives from joint index 1, believed at the time to be `prejoint`. Re-ran `retarget_anim` with `prejoint` added to `--root-joints` to test the obvious hypothesis - no change. **This joint identification turned out to be wrong — see the 6th round below.** Added temporary debug logging (`[turn-around-debug]` prefix) to get real runtime numbers on the next test instead of more static theorizing.
  - *Charged jump: character looks abnormally stretched throughout the whole animation* — not yet investigated to a conclusion. Confirmed `target-board-jump`'s high-jump branch does *not* use `compute-alignment!`/`align!` at all - height comes from physics (`transv`/gravity) with the animation's own playback speed scrubbed via `root-channel 0 param 0/1` to stay visually in sync with the physics arc (`time-to-apex`). That makes this a different category of problem from the turn-around issue above - most likely pose/rotation retargeting fidelity on individual limb joints not suiting Jak 2's proportions, rather than a root-motion/alignment bug. No fix attempted yet.
  - *Zap effect doesn't follow the board* — expected given the crash-fix design (a static one-time snapshot position, matching the native `group-board-spin-attack` pattern used for a `part-tracker-spawn`-owned effect). Attempted fix: switched to a dedicated `zap-part` launch control created directly on the target (mirroring `charge-part`) and spawned once per trigger, so `board-zap-track` could safely re-read the hips joint's live position every particle-update. **This broke the zap entirely (move and effect both stopped happening) and was reverted** - see the 5th playtest round below.
- **Regression (5th playtest round): the zap-part rework above broke the move completely.** Reverted `board-h.gc`/`board-part.gc`/`target-board.gc` back to the exact 4th-round (crash-fix) version: `part-tracker-spawn` with a plain snapshotted `:mat-joint` vector, `sparticle-track-root` as the particle `:func`, no `zap-part` field. Likely mechanism (not fully confirmed, but consistent with the symptom): `zap-part` was a *brand-new* struct field, unlike `charge-part` (added earlier, already proven stable across sessions) - the lazy-init guard `(if (zero? (-> self board zap-part)) (create-launch-control ...))` assumes that memory starts zeroed the first time, but a freshly-inserted field in a pooled process struct can start out holding leftover content from whatever previously occupied that memory. If the zero-check read that as non-zero, `create-launch-control` would never run, leaving `zap-part` pointing at garbage - spawning through it would silently do nothing rather than crash, which fits "disappeared" better than a crash would.
- **Sound logging cleanup (5th playtest round):** the blanket by-name lookup-failure logging added 2 rounds ago fired for every sound in the game, drowning the actually-relevant lines under constant, unrelated, pre-existing failures for ambient sounds (`PORT_AMB1`, `BARGE_ENGINE`, `BOW_WASH`, ...) that have nothing to do with this mod. Scoped `player.cpp`'s logging to fire only when the sound name contains "BOARD" (a plain substring check is enough - `sound_name` is already uppercased by `strcpy_toupper` before this RPC is issued). Also added a one-line, one-time-per-session GOAL log confirming the `sound-bank-load("board")` call from the previous fix actually executes, since the C++ side alone can't distinguish "board bank loads fine, individual sound names just don't match" from "the load call never even runs".
- **Turn-around — root cause found and fixed (6th playtest round).** The 4th round's `prejoint` identification for joint index 1 was wrong — it was reached by counting the GLB's raw joint array, the same mistake already made twice on the `board`/`hips` joint. Rebuilt the mapping from the actual GLTF parent/child hierarchy instead (not array position), using `build_actor.cpp`'s own indexing rule (game joint index = GLTF skin index + 1, `goalc/build_actor/common/build_actor.cpp`): index 1 is actually **`align`** (parentless and childless - genuinely isolated, as previously thought), not `prejoint`, which is index 2 (also parentless within the skin, but with `main` as its one child). The `[turn-around-debug]` log confirmed `align delta trans` is exactly `(0,0,0)` on every single frame of every turn attempted; a direct channel dump of the imported GLB then confirmed this is faithful to Jak 3's own source data — `align` carries zero translation keys in both imported clips, all real root motion is on `main` instead — so this was never a retargeting gap, on this port or the 4th round's. With the velocity formula's scaling factor always 0, it was zeroing the player's entire horizontal speed for the whole state instead of merely modulating it: the character free-fell straight down with no horizontal control for up to a full second on every attempt. The freeze reported after this round's test is the same bug compounding: the move visibly does nothing useful, so pressing Triangle again (a natural reaction) re-triggers it - the log shows at least 5 separate turn-around executions chained back to back with `pos-y` net-decreasing throughout, reaching roughly -10244 (raw units) by the time the log was captured, with brief `parking-spot::find-ground` ground contacts between attempts rather than a clean landing. Fixed the formula to match Jak 3's native math exactly (dropped the `target-align-vel-z-adjust` wrapper, which Jak 3 doesn't use here) and added a fallback: when the animation provides no root-motion signal, hold the entry speed instead of zeroing it, so the player keeps moving through the turn instead of stalling in place. This is a deliberate Jak-2-specific adaptation, not a literal port of Jak 3's formula, since the underlying data gap (no `align` motion) appears to be inherent to Jak 3's own source clip rather than something a retargeting fix could recover. Removed the now-explained `[turn-around-debug]` logging. **Not yet re-tested.**
- **Gun joint appears to drift away from the skeleton during both imported animations (6th round hypothesis, tested and disproven in the 7th).** The 6th round's theory - uncorrected rest/bind-pose mismatch between Jak 2 and Jak 3 compounding down `gun`'s parent chain (`gun → upper_body → waist_prog → main → prejoint`) - was implemented (rotation now retargeted as a delta from the source's own bind pose instead of a raw copy, `retarget_anim.cpp`, compiles clean) and regenerated into both GLBs, but a direct check of the actual bind-pose rotations for every joint in that chain, in both Jak 2's and Jak 3's native `jakb-lod0.glb`, found them **identical** `(0,0,0,1)` (pure identity) on both sides. With identical bind poses the delta computation is mathematically the same as a raw copy, which is exactly what was measured: a forward-kinematics comparison of `gun`'s world position relative to `main` across every frame, old retargeting vs new, came back byte-identical. **The rest-pose-mismatch hypothesis is wrong.** The fix is kept anyway (harmless, and strictly more correct for any future joint pair that does have mismatched bind poses), but it does not address this symptom. The FK check also didn't turn up anything obviously wrong in the data itself: `gun`'s distance from `main` traces a smooth, continuous, bounded arc (roughly 1.03-1.16m over the jump-high clip, no jumps or outliers) - which reads as ordinary arm-swing motion, not a bug. Since `gun` has no attached mesh to judge it against in Blender (confirmed - it's bone-only), it's possible this is genuine, intentional source motion that just looks like unexplained drift in isolation. **Need a screenshot or short clip of what this actually looks like to make further progress** - out of static-analysis leads on this one.
- **Audio — real root cause found and fixed (7th playtest round).** The new `[board-sound-debug]` logging pinpointed it immediately: `AllocateBankName "board": AllocateBankName failed (out of slots?)`. Read `game/overlord/common/sbank.cpp` directly - `InitBanks()` reserves 6 fixed bank slots at boot: `gBanks[0]`="common", `gBanks[1]`="gun", `gBanks[2]`="board", `gBanks[3..5]`=the 3 rotating level banks. But `AllocateBankName` only ever special-cased slot 0 ("common"/"commonj") with a direct return; every other name - including "board" and "gun" - fell through to a loop that starts at index 3, permanently skipping slots 1 and 2. Since a real level always keeps all 3 rotating slots full, any non-"common" named allocation was doomed to fail with "out of slots", even though 2 dedicated slots sat unused the entire time. This is a latent, pre-existing bug in the C++ port (present since this file was first written, unrelated to this mod) that nothing had ever triggered before, because nothing on Jak 2 ever requested "board" or "gun" by name through this path until the previous round's `sound-bank-load` fix started actually calling it. Fixed by adding the same direct-return special case for "gun" and "board" that "common" already had. Confirmed compiling cleanly (`cmake --build ... --target gk`). **Confirmed working in-game (8th playtest round) - board sounds now play.**
- **Charge-up sound specifically still missing (8th playtest round, after the above fix).** The launch/jump sound plays, but the looping charge-up sound (meant to build while holding L1) never does. Cause: `sound-play-by-name` (`engine/sound/gsound.gc`) doesn't generate a sound id itself - it just echoes back whatever id it's given, so a sound meant to be *updated* every frame (like this one, whose volume ramps with `charge-progress`) needs a real, unique id already sitting in `charge-sound-id` before the per-frame calls start, so the audio engine can recognize repeated calls as "update this same instance" rather than unrelated requests. Jak 3's `target-board-init` sets this up explicitly (`(set! (-> self board charge-sound-id) (new-sound-id))`, alongside 5 other sound-ids) - this line was simply never added when `charge-sound-id` was ported as a new field, unlike `charge-part` (which did get its init wired up). Fixed by adding the same `(new-sound-id)` call Jak 3 uses, in the same per-mount sound-setup block in `target-board-init`. **Not yet re-tested.**
- **Audio — root cause found and fixed (5th round, still not sufficient - see above).** Traced `og-j1-board`'s own working reference in detail (per explicit request): it doesn't just build a `.SBK`, it also patches `goal_src/jak1/engine/level/level.gc` to force-load its "board" bank exactly once, hooked into the vanilla per-tick `update-sound-banks`, guarded by a `*board-bank-loaded?*` flag — because a bank never gets loaded just by existing on disk; something has to explicitly request it. Checking Jak 2 for the equivalent request turned up nothing: `'board` doesn't appear in any of the ~40 per-continue-point `:want-sound` arrays in `engine/level/level-info.gc` (that's the actual data driving the native 3-slot bank rotation in `update-sound-banks`, `engine/level/level.gc`), and the existing `(set-setting! 'mode-sound-bank 'board 0.0 0)` call in `target-board-init` doesn't trigger a load either — its only reader in the whole codebase is a debug-HUD display line in `engine/sound/gsound.gc`. So the "board" bank — all 20 native sounds in it, not just the 4 this mod adds — was never actually being loaded during normal play; the `.SBK` structure, name-casing, and everything else checked below were never the problem. Fixed by adding an explicit, guarded `(sound-bank-load (static-sound-name "board"))` call in `target-board-init`, mirroring Jak 3's unconditional `commonj`/`common` load pattern already present natively in `gsound.gc` (a bank loaded this way sits outside the 3-slot rotation entirely, so it can't conflict with `update-sound-banks`'s own bookkeeping).
- **Audio — supporting investigation before the root cause above was found:** Exhaustively checked and *ruled out*: (a) the built `.SBK`'s name-table structure — parsed the actual output file in Python using the engine's own hash-bucket-chain format (`game/sound/989snd/loader.cpp`); all 4 new sounds are correctly present and reachable, same as the 20 native ones; (b) name-casing — `(sound-play "board-charge")` is packed byte-for-byte by `static-sound-name` (no transform), but `game/overlord/jak2/srpc.cpp:125` calls `strcpy_toupper` before the C++ lookup, which uppercases *and* converts `-` to `_` (`game/overlord/common/soundcommon.cpp:23-30`) — `"board-charge"` correctly becomes `"BOARD_CHARGE"`, matching the file; (c) bank loading — `target-board-init` already calls `(set-setting! 'mode-sound-bank 'board 0.0 0)` (native, untouched code), so the "board" bank should already load dynamically on any level. Checked directly against `og-j1-board`: their fix (standalone `build-sbk` bank + an explicit `sound-bank-load` patch) doesn't transfer here, since Jak 2 already has a native `BOARD.SBK` with a working load path — `append-sbk` remains the right choice, and its binary output is verified correct. What *was* found: the two log lines that would reveal a failed by-name lookup (`play_sound_by_name: failed to find ...`) were commented out in the engine. Reactivated and enhanced in `game/sound/989snd/player.cpp` (now also dumps every name actually registered in the bank via the pre-existing but never-called `SFXBlock::DebugPrintAllSounds()`). **This requires a full C++ engine rebuild** (`cmake --build out/build/Release --target gk`), not just `(mi)` — a verification build compiled the changed file cleanly but failed to link because `bin/common.dll` was locked (close any running REPL/`gk.exe` first). **Confirmed not a regression from that logging change:** a boot log showed many `play_sound_by_name: failed to find bank for sound ...` errors for `PORT_AMB1`, `BARGE_ENGINE`, `BOW_WASH` during the prison intro — none of these are board sounds. `git diff` on `player.cpp` shows the only change is the 2 uncommented `lg::error` lines; the bank-resolution logic itself (`GetBankByName`/`GetBankByHandle`/`GetBankWithSound`) is untouched, pre-existing code, so the board work can't be what broke this — it's a pre-existing silent failure for unrelated ambient sounds, now visible because logging is on. Still need the board-specific portion of a fresh log (after the crash fix, engine rebuild, and `(mi)`) to see whether `BOARD_CHARGE`/`BOARD_LAUNCH`/`BOARD_ZAP`/`BOARD_ZAP_HIT` fail the same way or differently.
